# PWA и уведомления чата

PWA устанавливается из меню браузера. Внизу сайта есть кнопка «Включить уведомления о сообщениях». Разрешение браузера запрашивается только по нажатию кнопки. Посетитель получает ответы на свой диалог; сотрудники с правом `chat.reply_conversation` получают сообщения посетителей. Каждому устройству нужно отдельно включить уведомления. Клик по уведомлению открывает переписку.

## Настройка сервера

1. Используйте HTTPS (для локальной разработки допускается localhost).
2. Один раз создайте ключи из каталога `tools_shop`:

   ```sh
   python manage.py generate_vapid_keys
   ```

3. Скопируйте выведенные `VAPID_PRIVATE_KEY` и `VAPID_PUBLIC_KEY` в `.env` и добавьте контакт администратора:

   ```dotenv
   VAPID_SUBJECT=mailto:admin@your-domain.ru
   ```

   Укажите реальный адрес. Приватный ключ храните в секрете. Сохраняйте одну пару ключей при повторных развёртываниях: смена ключей требует повторного включения уведомлений на устройствах.

4. Примените миграции и соберите статику:

   ```sh
   python manage.py migrate
   python manage.py collectstatic --noinput
   ```

5. Перезапустите приложение и Django Q (`python manage.py qcluster`). Для текущего Docker Compose:

   ```sh
   docker compose up -d --build web qcluster
   ```

   Существующий entrypoint web применяет миграции и собирает статику. Redis и qcluster нужны для фоновой отправки. Зависимость `pywebpush` уже есть в requirements.txt.

## Проверка на устройстве

- Откройте сайт по HTTPS, установите PWA через меню браузера и включите уведомления кнопкой внизу страницы.
- На iPhone/iPad нужен iOS/iPadOS 16.4+: Safari → «Поделиться» → «На экран Домой», затем запустите приложение с экрана Домой и включите уведомления внутри него.
- На устройстве оператора войдите под сотрудником с правом отвечать в чате и включите уведомления.
- Отправьте сообщение с другого браузера. Сверните приложение оператора, проверьте уведомление и переход в диалог. Отправьте ответ и проверьте уведомление посетителя.
- Проверьте выключение уведомлений кнопкой. Если браузер запретил уведомления, разрешение нужно вернуть в настройках сайта.

Уведомления приходят через push-службу браузера даже при закрытой вкладке, если браузер/ОС допускает фоновую доставку. Принудительное завершение браузера и системные ограничения могут задерживать доставку. В уведомлении видны первые 160 символов сообщения. Подписки удаляются при ответе push-службы 404/410 и при обнаружении истёкшей/закрытой сессии. Проверка сессии оператора защищает от доставки после выхода из аккаунта.

HTML и ответы API не сохраняются в offline-кеш: текущая версия требует сеть для работы магазина и чата. Иконки 180/192/512 созданы из `shop/static/shop/images/fav1.png`. Service Worker выдаётся по `/sw.js` с областью `/`.

## Автоматические проверки

```sh
python manage.py test chat --settings=chat.test_settings
```

Тесты используют SQLite и локальные аналоги Redis/Channels; отправка в push-службы замокана. Они не подтверждают фактическую доставку на устройство.
