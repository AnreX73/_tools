# Чат с посетителями

Кнопка находится справа внизу на страницах магазина. Никаких таймеров,
автоматического открытия, звуков и подключения WebSocket до нажатия нет.
При закрытии соединение прекращается. История сохраняется в PostgreSQL;
при повторном открытии показываются последние 100 сообщений.
Гость идентифицируется серверной Django-сессией. После очистки cookies
или в другом браузере будет новый диалог.

## Запуск

Из `tools_shop` в активированном виртуальном окружении:

```sh
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Нужны PostgreSQL и Redis с параметрами из `.env`.
Daphne подключён к `runserver`; WSGI-сервер WebSocket не поддерживает.
Docker:

```sh
docker compose up -d --build
```

Web-контейнер запускает Daphne и выполняет миграции. Конфигурация
`conf/nginx.conf` передаёт WebSocket Upgrade. В Nginx Proxy Manager
включите Websockets Support и HTTPS. Укажите домен в ALLOWED_HOSTS
и https://домен в CSRF_TRUSTED_ORIGINS. Для production включите
SESSION_COOKIE_SECURE и CSRF_COOKIE_SECURE. Не публикуйте Daphne напрямую:
проект доверяет заголовкам reverse proxy.

## Работа менеджера

Войдите через `/admin/login/`, затем откройте `/chat/operator/`.
Для сотрудника нужны `is_staff` и право
`chat | Диалог | Может отвечать посетителям в чате`.
Суперпользователь имеет доступ автоматически. Диалоги также доступны
в админке с ссылкой «Открыть чат».
Список последних 100 диалогов обновляется вручную; внутри диалога сообщения
приходят через WebSocket. Чат не утверждает, что менеджер онлайн.

## Защита и ограничения

- CSRF при создании диалога, проверка Origin для WebSocket.
- Гостевой WebSocket не принимает ID диалога от клиента.
- Роль отправителя определяется сервером, текст выводится через `x-text`.
- До 2000 символов, до 20 сообщений в минуту на диалог и сторону отправителя.
- Идентификаторы сообщений предотвращают дубли при повторной отправке.
- Черновик очищается после подтверждения, переподключение ограничено 5 попытками.

Перед публичным запуском настройте ограничения запросов на уровне proxy
(особенно `/chat/start/` и WebSocket handshake) и политику хранения/удаления
переписки. Уведомления менеджеру, вложения, индикатор присутствия и поиск
по старой истории в эту версию не входят.

## Проверка

```sh
python manage.py check
python manage.py test chat --settings=chat.test_settings
```

Тесты используют отдельную SQLite in-memory БД, локальный cache и in-memory
channel layer; рабочую БД не меняют. Проверка реальной PostgreSQL/Redis,
reverse proxy и UI в браузере выполняется отдельно.
