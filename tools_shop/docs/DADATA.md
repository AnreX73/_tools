# Подключение DaData к оформлению заявки

Интеграция уже написана. Она включается настройками окружения: без ключа
сайт продолжает работать, повторные клиенты подгружаются из базы, а новым
клиентам показывается сообщение, что автозаполнение не настроено.

## Что происходит при вводе ИНН

Подсказка срабатывает двумя способами:

* автоматически — через 800 мс после того, как в поле ИНН набрано 10 или
  12 цифр (промежуточные значения на сервер не отправляются);
* по кнопке «Заполнить по ИНН» — если нужно повторить запрос или заполнить
  КПП после ввода ИНН.

Дальше:

1. ИНН и КПП нормализуются и проверяются на сервере.
2. Сначала выполняется поиск активной организации в `LegalEntity` по паре
   `(inn, kpp)`.
3. Если организация найдена, в форму подставляются только публичные
   реквизиты из базы. DaData не вызывается.
4. Если организации нет, выполняется запрос к DaData
   `findById/party`.
5. Ответ маппится в поля формы. Юридический адрес, ОГРН и ОПФ подставляются;
   банковские реквизиты и контакты остаются ручными.
6. При любой ошибке DaData форма не блокируется: показывается сообщение и
   можно заполнить всё вручную.

Из карточки в базу формы **не** попадают `email`, `phone`, `contact_name`,
банковские счета и примечания. Это сделано специально: по ИНН карточку может
запросить любой человек, а контакты относятся к конкретному покупателю.

## 1. Получить API-ключ

1. Зарегистрируйтесь на <https://dadata.ru/>.
2. Подтвердите email.
3. Откройте личный кабинет и скопируйте API-ключ.
4. Для Suggestions API (`findById/party`) достаточно API-ключа. Секретный
   ключ нужен только для методов стандартизации; поле
   `DADATA_SECRET_KEY` можно оставить пустым.

Бесплатный тариф DaData — до 10 000 запросов в день. Успешные ответы
кэшируются, поэтому повторные проверки одного ИНН не расходуют квоту.

## 2. Прописать переменные в `.env`

```env
DADATA_API_KEY=ваш_api_ключ
# Необязательно, только для clean-методов:
DADATA_SECRET_KEY=

DADATA_TIMEOUT=5
DADATA_CACHE_TTL=86400
DADATA_RATE_LIMIT=10
DADATA_RATE_WINDOW=60
# Лимит подсказок в админке (менеджер проверяет несколько контрагентов подряд):
DADATA_ADMIN_RATE_LIMIT=30
```

`DADATA_CACHE_TTL` — время жизни кэша ответа в секундах (по умолчанию сутки).
`DADATA_RATE_LIMIT` и `DADATA_RATE_WINDOW` — ограничение кнопки подсказки:
10 запросов в минуту с одного IP. `DADATA_ADMIN_RATE_LIMIT` — отдельный лимит
для админки в том же окне `DADATA_RATE_WINDOW`.

Ключ читается только на сервере. В шаблоны, HTML и JavaScript он не
передаётся.

## 3. Перезапустить приложение

После изменения `.env` перезапустите Django. Для проверки:

```powershell
..\.venv\Scripts\python.exe manage.py check
```

Ошибок быть не должно. Отдельная миграция не нужна: используются уже
существующие поля `LegalEntity`, а в форму добавлено только поле ОГРН.

## 4. Проверить вручную

1. Откройте оформление заявки.
2. Введите ИНН Сбербанка `7707083893` и КПП `773601001`.
3. Через секунду после ввода ИНН поля заполнятся сами. Кнопка «Заполнить
   по ИНН» делает то же самое по требованию.
4. Должны заполниться наименование, ОПФ, ОГРН и юридический адрес.
5. Нажмите кнопку ещё раз: если организация уже есть в базе, данные придут
   из базы, а не из DaData.

Для проверки ИП используйте ИНН `500100732259`, КПП оставьте пустым.

## 5. Автозаполнение в админке

В админке подсказка работает у двух моделей: «Реквизиты продавца»
(`SellerProfile`) и «Юридические лица» (`LegalEntity`).

- Ввод ИНН (10 или 12 цифр) через 800 мс заполняет незаполненные поля и
  значения, которые менеджер не менял руками: ОПФ, краткое и полное
  наименование, КПП, ОГРН, юридический адрес. Ручные правки не затираются.
- Кнопка «Заполнить по ИНН» перезаписывает все эти поля; если что-то уже
  заполнено, админка спросит подтверждение.
- Банковские реквизиты, контакты и руководитель не заполняются: DaData их
  в `findById/party` не отдаёт.
- Запросы идут на `POST /admin/inn-lookup/` (только для staff, с CSRF) и
  возвращают JSON. Лимит — `DADATA_ADMIN_RATE_LIMIT` в минуту.

## 6. Где смотреть ошибки

- `DADATA_API_KEY не задан` — ключ не попал в окружение.
- HTTP `401`/`403` — неверный ключ или закончился доступ.
- HTTP `429` — превышен лимит DaData; подождите или проверьте тариф.
- Таймаут — сеть или DaData недоступны; форма останется доступной.
- «Организация не найдена» — проверьте ИНН/КПП; для ИП КПП не указывается.

Логи пишутся стандартным логгером Django. Тело ответа DaData и ключи в лог
не попадают.

## 7. Тесты

Тесты не ходят в реальный DaData: HTTP-вызовы подменяются через `mock`.

```powershell

```
