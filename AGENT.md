# Правила обработки запросов

## Структурирование запросов перед началом работы

Перед выполнением любого запроса пользователя:

1. **Проанализируй запрос** — выдели ключевые элементы из сумбурного изложения:
   - Основную цель/задачу
   - Конкретные требования
   - Примеры (если есть) и что они иллюстрируют
   - Контекст и ограничения
   - Ожидаемый результат

2. **Структурируй запрос** в четком формате:
   ```
   ## Понял задачу:
   
   **Цель:** [основная задача одним предложением]
   
   **Требования:**
   - [требование 1]
   - [требование 2]
   - ...
   
   **Детали:**
   - [важная деталь 1]
   - [важная деталь 2]
   
   **Ожидаемый результат:** [что должно получиться]
   
   ---
   Правильно понял? Если да, приступаю к работе.
   ```

3. **Дождись подтверждения** пользователя перед началом работы.

## Исключения

Не применяй структурирование, если:
- Запрос уже четко сформулирован и структурирован
- Это простой вопрос, требующий короткого ответа
- Пользователь явно просит "действуй сразу" или "без уточнений"

## Примеры сумбурных запросов

**Сумбурный запрос:**
> "Мне нужно что-то типа как в том проекте, помнишь, где мы делали валидацию, но тут другое, тут надо чтобы оно само проверяло и ещё логировало ошибки, ну и чтобы можно было настроить через конфиг, типа json файл или что-то такое"

**Структурированное понимание:**
```
## Понял задачу:

**Цель:** Создать систему валидации с автоматической проверкой и логированием

**Требования:**
- Автоматическая проверка данных
- Логирование ошибок валидации
- Настройка через конфигурационный файл (JSON)

**Детали:**
- Взять за основу подход из предыдущего проекта валидации
- Адаптировать под текущие нужды

**Ожидаемый результат:** Модуль валидации с конфигурируемыми правилами и встроенным логированием

---
Правильно понял? Если да, приступаю к работе.
```
